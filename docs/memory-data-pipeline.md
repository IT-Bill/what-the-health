# 聊天数据采集与报告生成方案

## 概述

Memory 页面的周报、月报和 AI 洞察，其原始数据全部来源于用户与 Mindful 的日常对话。本文档定义：

1. 我们需要从对话中提取哪些结构化信息
2. 如何在自然对话中引导用户提供这些信息（不让用户觉得是在填表）
3. 如何通过 LLM 将非结构化对话转换为数据库所需的结构化数据

---

## 一、需要采集的信息维度

根据 Report 和 Insight 表的 `data` 字段设计，我们需要以下维度的原始数据：

| 维度 | 需要的信息 | 对应 Report 字段 | 采集频率 |
|------|-----------|-----------------|---------|
| 情绪 | 当前心情、情绪强度、触发事件 | `moodEmojis`, insights | 每次对话 |
| 睡眠 | 入睡时间、起床时间、睡眠质量主观评价、是否做梦/中断 | `sleepData`, stats | 每日 |
| 运动 | 类型、时长、强度、主观感受 | stats, highlights | 发生时 |
| 饮食 | 餐次、大致内容、特殊摄入（咖啡因、酒精） | stats, insights | 每日 |
| 身体不适 | 症状描述、部位、严重程度、持续时间 | stats("异常上报") | 发生时 |
| 正念/习惯 | 是否完成、持续时间、主观体验 | stats("正念练习") | 每日 |
| 能量水平 | 精力充沛程度（1-5） | overallScore 计算因子 | 每次对话 |
| 压力/焦虑 | 压力来源、程度、应对方式 | insights(pattern) | 出现时 |

### 中间存储：ChatExtraction 表（建议新增）

每次对话结束后，LLM 提取的结构化信息存入一个中间表，作为报告生成的原料：

```
ChatExtraction {
  id
  sessionId       → 关联对话
  userId
  extractedAt
  date            → 这条信息描述的是哪一天
  type            → mood | sleep | exercise | diet | symptom | mindfulness | energy | stress
  data: Json      → 结构化内容（见下方 schema）
  confidence      → LLM 提取置信度 0-1
}
```

每种 type 的 `data` schema：

```typescript
// mood
{ emoji: "😊" | "😐" | "😴" | "😢" | "😡", intensity: 1-5, trigger?: string }

// sleep
{ bedtime?: "23:30", wakeTime?: "07:00", hours?: 7.5, quality: 1-5, notes?: "中间醒了一次" }

// exercise
{ type: "跑步" | "瑜伽" | ..., durationMin: 30, intensity: "low" | "medium" | "high", feeling?: string }

// diet
{ meal: "breakfast" | "lunch" | "dinner" | "snack", description: string, caffeine?: boolean, alcohol?: boolean, time?: "12:30" }

// symptom
{ symptom: "头痛" | "腹胀" | ..., severity: 1-5, duration?: "2小时", bodyPart?: "头部" }

// mindfulness
{ type: "呼吸" | "冥想" | "正念行走", durationMin: 5, feeling?: string }

// energy
{ level: 1-5, time: "morning" | "afternoon" | "evening" }

// stress
{ level: 1-5, source?: string, copingStrategy?: string }
```

## 二、对话引导策略

### 核心原则

1. **不要像问卷**：不能连续问 "你今天睡了几个小时？运动了吗？吃了什么？" 
2. **跟随用户节奏**：用户说什么就顺着聊，在自然过渡中追问细节
3. **每次对话 1-2 个追问**：不贪心，信息逐步积累
4. **缺失信息不强求**：用户不想说就不追问，下次再问
5. **给出回报感**：让用户知道这些信息会帮助他们（"这样我能更好地了解你的模式"）

### 引导时机矩阵

| 用户说了什么 | 顺势追问 | 采集到的维度 |
|---|---|---|
| "今天好累" | "是身体累还是心累？昨晚睡得怎么样？" | 能量、情绪、（引出睡眠）|
| "失眠了" | "大概几点才睡着的？" | 睡眠 |
| "头疼" | "从什么时候开始的？现在还在疼吗？" | 症状 |
| "刚跑完步" | "跑了多久？现在感觉怎样？" | 运动 |
| "心情不错" | "是有什么好事发生吗？" | 情绪 + trigger |
| "喝了杯咖啡" | "下午喝的吗？最近睡眠和咖啡时间有没有关系？" | 饮食(咖啡因) |
| "做了冥想" | "做了多长时间？做完有什么感觉？" | 正念 |
| "压力好大" | "是工作上的还是？现在身体有没有哪里紧绷？" | 压力、可能引出症状 |

### 主动触发（如果用户没有主动提到）

每天的第一次对话中，Mindful 可以用以下方式温和开启：

```
早上（6:00-11:00）：
- "早安。昨晚休息得还好吗？"  → 采集睡眠
- "新的一天，现在感觉怎么样？" → 采集情绪、能量

下午（13:00-18:00）：
- "下午了，今天到现在状态如何？" → 采集能量、情绪

晚上（19:00-23:00）：
- "一天快结束了，今天身体有没有什么不舒服的地方？" → 采集症状
- "今天有运动吗？" → 采集运动（如果本周还没记录过）
```

**关键**：这些触发不应每天都用，而是根据缺失数据智能选择。例如：
- 如果用户已经3天没提到睡眠 → 优先问睡眠
- 如果这周还没有任何运动记录 → 温和问一次运动
- 如果用户上次说了头疼 → 追踪 "昨天头疼好了吗？"

### System Prompt 中的引导指令

在 Mindful 的 system prompt 中追加采集指令（不暴露给用户）：

```
## 数据采集（内部指令，不要向用户提及"采集"或"数据"）

你在对话中需要温和地了解用户以下方面的信息，但不要让对话变成问卷：
- 情绪状态和触发因素
- 睡眠情况（时间、质量）
- 运动情况
- 饮食（特别是咖啡因和酒精）
- 身体不适
- 正念/冥想练习
- 能量和压力水平

规则：
1. 每次对话最多追问 1-2 个维度的细节
2. 优先跟随用户当前话题自然追问
3. 如果用户明确不想聊某个话题，立即尊重并切换
4. 在对话自然结束时（如果还缺少重要维度），可以温和地开启一个新话题
5. 优先追问与用户当前状态高度相关的维度（如：用户说累→睡眠；用户说焦虑→压力来源）
```

## 三、对话 → 结构化数据的转换

### 流程架构

```
用户对话 (ChatMessage[])
       │
       ▼
┌──────────────────────┐
│  LLM 提取 Pipeline   │  ← 每次对话结束时（或流式提取）
│  (异步后台任务)       │
└──────────────────────┘
       │
       ▼
ChatExtraction (中间表)
       │
       ▼ 定时聚合 (每日/每周/每月)
┌──────────────────────┐
│  Report 生成 Pipeline │
└──────────────────────┘
       │
       ├──▶ Report 表 (聚合指标)
       └──▶ Insight 表 (AI 发现的模式)
```

### Step 1: 对话结束后的实时提取

每次对话（ChatSession）结束或达到一定轮次后，调用 LLM 提取结构化信息。

**提取 Prompt：**

```
你是一个健康数据提取助手。请分析以下对话内容，提取出用户提到的健康相关信息。

对话内容：
---
{chat_messages}
---

请以 JSON 格式输出提取到的所有信息。如果某个维度没有提到，就不要编造。
只提取用户明确表达或可以高度确信推断的信息。

输出格式：
{
  "extractions": [
    {
      "type": "mood" | "sleep" | "exercise" | "diet" | "symptom" | "mindfulness" | "energy" | "stress",
      "date": "YYYY-MM-DD",  // 信息描述的日期，如果用户说"昨天"则推算
      "data": { ... },       // 根据type对应的schema
      "confidence": 0.0-1.0, // 你对这条提取的确信程度
      "source_quote": "..."  // 用户原话（用于可追溯性）
    }
  ]
}

注意：
- 用户说"还行"可能是6-7分，"很好"是8-9分，"很差"是2-3分
- 如果用户说"昨晚没睡好"但没说具体时间，只记录 quality: 2-3，不编造时间
- 情绪 emoji 映射：开心/不错→😊，一般/还行→😐，累/困→😴，难过→😢，生气/烦→😡
- confidence < 0.6 的提取将被标记为低确信度，不直接用于报告
```

### Step 2: 定时报告生成

#### 每日汇总（用于周报累积）

每天 UTC 0:00 跑一次任务，把当天的 ChatExtraction 聚合：
- 确定当天的 mood emoji（取最后一次情绪，或最高频情绪）
- 计算睡眠时长（取 sleep 类型中 hours 字段）
- 累计运动次数和时长
- 统计异常上报次数

#### 周报生成（每周一）

```
输入：本周 7 天的每日汇总 + 本周所有 ChatExtraction

生成逻辑：
1. moodEmojis = 7天的每日emoji
2. sleepData = 7天的每日睡眠时长
3. stats = [
     睡眠均值 + 与上周对比,
     异常上报次数 + 与上周对比,
     修复采纳率 = (用户按建议做的次数 / 给出建议的次数),
     正念练习次数 + 与上周对比,
   ]
4. overallScore = 加权平均(情绪稳定度*25 + 睡眠质量*30 + 运动达标*20 + 异常少*25)
5. highlights = 本周最显著的变化
6. achievements = 检查是否触发里程碑（连续N天、指标突破等）
```

#### 月报生成（每月1日）

与周报类似，但范围是30天，额外包含：
- 月度趋势对比（vs 上月）
- 长期里程碑检测（连续30天XX）
- 可分享报告卡数据

### Step 3: 洞察/模式发现

独立的 LLM 分析任务，输入是累积的 ChatExtraction 数据：

**模式发现 Prompt：**

```
你是一个健康数据分析师。以下是用户过去 N 天的健康数据记录。
请分析是否存在有价值的模式、关联或趋势。

数据：
{extractions_grouped_by_date}

请输出发现的洞察，格式：
{
  "insights": [
    {
      "type": "pattern" | "prediction" | "correlation" | "milestone",
      "title": "简短标题",
      "content": "对用户友好的描述（中文，口语化，有温度）",
      "confidence": 0.0-1.0,
      "metadata": {
        "relatedFactors": [...],
        "strength": 0-100,       // 关联强度（correlation类型）
        "severity": "low|medium|high",
        "evidence_count": N      // 支持这个结论的数据点数量
      }
    }
  ]
}

分析要求：
1. 至少需要 3 个以上数据点支持才输出一个 pattern
2. correlation 需要明确的时间先后关系（A发生后B更容易发生）
3. prediction 必须基于已发现的 pattern，不能凭空预测
4. 表述要温和、建设性，避免焦虑感（不要说"你有问题"，而是"我注意到一个规律"）
5. milestone 只在确实达成时触发（连续7天以上的正向行为）
```

### 置信度与数据质量控制

| confidence 区间 | 处理方式 |
|----------------|---------|
| 0.8 - 1.0 | 直接用于报告和洞察 |
| 0.6 - 0.8 | 用于报告，洞察需要额外验证 |
| 0.4 - 0.6 | 仅用于趋势参考，不单独展示 |
| < 0.4 | 丢弃，不入库 |

## 四、实现建议

### 阶段一（当前）
- [ ] 新增 `ChatExtraction` 表
- [ ] 对话结束时调用 LLM 提取 → 存入 ChatExtraction
- [ ] 手动/定时触发报告生成脚本

### 阶段二
- [ ] System prompt 加入引导指令
- [ ] 实现智能追问（基于本周已采集/缺失的维度）
- [ ] 实时提取（对话过程中流式提取，不等结束）

### 阶段三
- [ ] 跨周/跨月的长期模式分析
- [ ] 用户反馈闭环（"这个洞察有用吗？"→ 调整未来洞察权重）
- [ ] 对话质量评估（本次对话采集到了几个维度？引导是否自然？）

### 技术栈选择

| 环节 | 方案 |
|------|------|
| 提取 LLM | 同聊天模型（GLM-5.1 via AI Ping），JSON mode |
| 定时任务 | Vercel Cron / 独立 worker / Next.js Route Handler 手动触发 |
| 提取触发 | 对话结束时（session 30min 无新消息）|
| 报告生成 | 周一 UTC 0:00 生成上周报告；每月1日生成上月报告 |
| 洞察生成 | 每周一和有新 pattern 数据积累时 |

## 五、数据流示例

```
用户: "今天头有点疼，可能是昨晚没睡好"
Mindful: "头疼从什么时候开始的？昨晚大概几点睡的？"
用户: "下午开始的。昨晚大概1点多才睡"
Mindful: "凌晨1点入睡确实比你平时晚了不少..."

→ LLM 提取:
[
  { type: "symptom", date: "2025-05-30", data: { symptom: "头痛", severity: 3, duration: null, bodyPart: "头部" }, confidence: 0.9 },
  { type: "sleep", date: "2025-05-29", data: { bedtime: "01:00", hours: null, quality: 3 }, confidence: 0.85 }
]

→ 周报聚合时:
  - 5/30 的 mood: 😐（因为有头痛+疲惫）
  - 5/29 的 sleep: ~5-6h (推算)
  - 异常上报 +1

→ 洞察分析（积累多次后）:
  { type: "correlation", title: "睡眠不足引发头痛", content: "...", strength: 72 }
```

## 六、隐私与伦理

1. **数据所有权**：所有提取的数据归用户所有，用户可随时删除
2. **透明性**：Memory 页面本身就是"AI 记住了什么"的展示，天然透明
3. **不诊断**：洞察的措辞始终是"我注意到..."、"可能有关联..."，不做医学诊断
4. **低确信度不展示**：避免给用户错误的健康焦虑
5. **退出机制**：用户可以在设置中关闭数据采集，此时 Mindful 退化为纯聊天模式
